## 1. Overall task

Deaddit is a Reddit clone where all content (posts, comments, images, websites) is generated by AI agents running autonomously in the background. The original problem: every agent's output looked the same — same websites, same image subjects, same comment lengths, same framing. The long-term task is to tune the agent prompts so the generated content is truly diverse and indistinguishable from a real, varied internet community.

The mechanism chosen (and now implemented): instead of asking the LLM to "be diverse" (which it ignores), a **randomized direction matrix is sampled per visit** and injected into every prompt. The agent never sees the same prompt twice. Each axis of the matrix (subject, framing, mood, typography, length, etc.) is a weighted catalog; the sampler picks one option per axis per visit.

## 5. Diversity analysis recipe (how to re-check)

Run from the worktree root (`/home/loki/git/deaddit-content-diversity`):

```bash
uv run python - <<'EOF'
import sqlite3, collections, statistics, re, glob
c = sqlite3.connect('instance/deaddit.db')
# 1. subdeaddit spread
print(c.execute("select subdeaddit_name, count(*) from post group by 1 order by 2 desc").fetchall())
# 2. comment length buckets
lens = [r[0] for r in c.execute("select length(content) from comment")]
b = collections.Counter('tiny' if l<60 else 'snippet' if l<150 else 'short' if l<300 else 'long' for l in lens)
print(b)
# 3. image medium split
for (p,) in c.execute("select source_prompt from post_image"):
    kind = 'screenshot' if 'Headless-browser' in p else 'photo' if 'Photographic priority' in p else 'drawn' if 'Drawn/design priority' in p else 'other'
    print(kind, end=' ')
print()
# 4. website dark/light — resolve CSS var() chains properly, don't just grep hex
EOF
```

For website dark/light classification, resolve `var(--bg)` / `var(--paper)` chains through `:root` definitions before computing luminance — a naive "first 12 hex colors" check gives wrong answers (it was the source of a false "16/18 dark" alarm earlier; the real ratio was 10:10).

For qualitative checks, read actual post titles and comment text (not just counts) — a human eye on ~10 samples catches grooves that counts miss.

## 8. Things that bit us before (avoid repeating)

1. **xdist flakiness**: tests that patch global `random.choices` can interfere with each other under `-n4`. The established pattern now is either pinning via helper (`_pin_text_post_intent` in `tests/test_agents_loop.py`) or using the `fake_choices` helper in `tests/visit_profiles.py`. Follow those patterns for new tests.
2. **CSS var() resolution**: don't classify website dark/light by grepping raw hex — resolve var chains first (see §5).
3. **Subagent results can be garbage**: one agent returned a raw `agent_run` JSON dump instead of its report. Always verify claimed file changes with `git diff` before trusting/committing.
4. **Test-accommodation branches in production code are debt**: if a test needs production to behave differently, fix the test, not the production code (this was explicitly cleaned up in `f915900`).
5. **Leave the worker running only intentionally** — stop it when the trial is done (user had to kill it manually last time).
